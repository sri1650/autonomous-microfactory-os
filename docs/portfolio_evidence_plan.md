# Portfolio Evidence Plan

The repository should eventually prove each capability with a concrete artefact.

| Capability | Evidence to capture |
|---|---|
| Software architecture | architecture diagram + ADRs + package boundaries |
| Python engineering | typed domain/orchestrator/scheduler code + tests |
| Rust engineering | runtime state machine + gRPC + clippy/tests |
| Fleet planning | benchmark CSV + animation/screenshot + conflict tests |
| Scheduling | FIFO vs CP-SAT makespan/latency report |
| Vision | labelled fixtures + latency/error metrics + decision policy |
| Reliability | fault-injection matrix + failure/recovery E2E test |
| Observability | trace screenshot + ClickHouse query + correlation example |
| Replay | deterministic digest demonstration |
| AI/agent evaluation | fault corpus + unsafe recommendation rate + abstention metrics |
| CI | green workflow screenshot/status |
| Demo | 3-minute walkthrough with exact scenario/seed |

## CV bullet rule
Do not write quantitative CV bullets until a benchmark or test has produced the number. Store the command and generated artefact beside every claim.
